## 基线与边界

本次 git ls-remote 再次确认 origin/main 为 cb0d6a658d1dc57c45ef3e6092d9f15c66386b7b。本地 HEAD 仍为 6fa6b00，用户改动保留。核对该固定提交的 packages/telegram/src/snapshot.ts、liveness.ts 和 packages/shared/src/site-data.ts，确认只有频道有 posts，抓取失败可能表现为 unknown，不能将其当作已成功取得的空简介。

规则只决定可用证据及是否允许尝试生成。进入生成不等于批准发布。语义充分性和矛盾不能保证用关键词自动判断，明显的空资料由确定性规则跳过，歧义由模型评估或人工复核。模型也可返回 insufficient。实测前不承诺自动判定准确率。

## 判定顺序与结果

1. 先确认条目仍为 approved 且在本次处理范围，人工锁定则保留版本，进入复审流程。删除或隐藏资源不生成。
2. 区分已成功取得的空资料、没有采集该类资料、读取失败。缺失的非必需来源不妨碍使用另一份充分证据。临时失败保留已有数据，不清空或替换旧证据。
3. 应用帖子显示过滤，删除控制字符、空白噪声并去重，广告和联系方式从摘要证据中排除。保留明示功能、主题、使用条件及必要实体。来源中的指令按文本处理，禁止执行。
4. 无可表述用途或主题时 skipped。有明确事实时 eligible。明确矛盾或可能误导时 needs_review。资料获取失败并导致无法形成可信输入时 retry_wait，有限次数耗尽后 failed。
5. eligible 送模型后仍需 schema、引用、语种及事实审阅。可发布内容沿用初期全审规则。其他结果继续使用现有首段，已有批准内容是否可继续展示取决于证据有效性。

| 判定 | 建议原因码 | 推理与再处理 |
| --- | --- | --- |
| eligible | profile_supported、posts_supported | 允许尝试推理，当前生成键去重 |
| skipped | no_substantive_evidence | 预检判定时零推理；实质输入或规则变化才重评 |
| skipped | model_insufficient | 已调用用量正常计入；同生成键不自动循环重试 |
| needs_review | source_conflict、ambiguous_scope | 记录候选审核问题，人工解决或来源变化后重评 |
| retry_wait | source_rate_limited、source_timeout、source_parse_error、source_read_error | 按技术错误有限退避，不能通过清空资料转 skipped |

以上是新模块内部决策，不新增假定的 Telegram 字段。步骤二定义从现有快照及 R2 读取结果映射的内部来源健康状态。候选审核状态 needs_review 与任务状态分开；推理前发现冲突时也要存可审核的诊断记录，无须强行生成候选正文。

## 分类型证据门槛

频道可依据简介写定位，或依据明确公开帖子写“可见样本涉及”的限定说明。单帖不能支持长期定位或频率结论。多帖主题不同本身不构成矛盾。原简介与帖文明示互斥功能、收费或范围时待审。只对图片、链接标题和模型常识有印象时跳过，不访问外链补证据。

群组主要依据公开简介。名称、分类、标签、人数、创建时间和是否有邀请链接，均不足以推断讨论主题、质量或活跃度。简介明示主题即可生成短句，规则链接的存在不证明链接里的具体规则。

机器人主要依据简介明示功能。名称和启动参数不足以推断功能。明确描述“支持某操作”可表述为其公开说明的功能，不能写成已实测可靠、免费或安全。宣传性词语如“精准”“必备”“最好”删去。

长度只用于成本和防滥用上限，不独自判定充分性。“PDF 转图片”有用途，长篇广告仍可能没有可用事实。category、tags 和 title 用于实体识别与理解上下文，具体用途须在实质简介或频道帖子中有证据。

## 证据记录与验收

每个固定样本保存来源类型、日期或固定版本、输入、预期决策、原因、允许断言和禁止外推。真实快照样本只说明当时记录，不能声称当前 Telegram 仍相同。构造案例使用虚构标识，不能归因于真实资源。

步骤一完成基线核对、真实样本选择、三类型边界案例及人工期望编制。步骤二将这些案例转成可执行契约测试，模型质量评估在步骤四执行。当前没有运行模型、生产抓取或业务代码测试。
