## 平台能力

Cloudflare目前提供Web Search API，可用REST的 /accounts/{account_id}/ai/websearch/ 或Worker的 env.AI.websearch()。请求经AI Gateway，需要Gateway额度或供应商密钥；Workers Paid订阅本身不能代替这项前置条件。Gemma可通过工具调用提出搜索请求，应用执行并将结果返回模型；给提示词写“联网查询”不会自动赋予网络能力。

Web Search用于发现网页；取得URL后仍需读取具体页面、保留证据并核对资源身份。AI Search针对已建索引的数据源检索，不等于直接搜索整个互联网。本方案只需普通Worker、现有D1/Queues/R2、搜索API及有限页面读取，不需要Durable Objects、VPS或引入完整Agents框架。

官方搜索工具说明最低本地运行时要求Wrangler4.141.0；项目 pnpm-workspace.yaml 当前固定4.132.0，生成类型无websearch。若采用binding，应有针对性升级并重生成类型、验证运行时；REST也是可选路径，不能直接照搬示例假定当前工具链支持。

## 对本项目的建议

联网触发条件为缺少用途、具体功能或官方说明，不是“句子写不好”“没达到字数”。资料明确但文风单调时继续做编辑优化，不搜索其他目录的AI改写来填字。

建议采用有界补全流程：

1. 先检查现有Telegram简介和可见公开帖子。已有资料充足则直接生成；主动隐藏条目不搜索。
2. 缺事实时建立独立异步补全任务。程序按精确username、Telegram链接以及来源已关联的官方域名构造查询，模型可提出缺失项，程序决定是否允许。
3. 优先已知官方链接直接读取，再使用搜索发现候选。初期每条至多2次搜索、每次最多3个候选、读取最多2页；这些为建议上限，不是当前已实现配置。
4. 核对是否同一资源：精确Telegram身份和可信站点之间的关联链，不只比对名称。优先资源自己的公开资料、明确关联的官网及维护者仓库。目录、转载或AI描述仅作发现线索，不独立证明功能和身份。
5. 记录来源URL、读取时间、可用发布日期、原文片段和内容哈希，清洗网页指令后才交给模型。搜索摘要不当作最终事实，旧说明、同名资源和冲突转待审；失败或仍不足继续回退现有摘要。
6. 外部资料先用于受审草稿，不直接发布。缓存搜索和抓取结果，设独立额度、次数和负面缓存；不阻塞投稿、审核或静态构建。

隐私、安全、免费、官方身份等声明仍需对应原文及可靠身份链。网页中的指令与推广均为不可信内容。已隐藏帖子不能通过外部转载重新引入；可明确识别的隐藏ID和屏蔽规则继续应用，无法确认的转载来源先待审，不声称能自动识别所有隐藏内容复制。

## 与当前契约的差距

packages/shared/src/ai-summary.ts 的EvidenceRef目前只接受profile和post:<id>，提示词也只允许既有evidence。不能把搜索文字直接拼进去而绕过契约。

实施前需另行设计web证据命名空间、来源/身份校验状态、清洗规则、可见性约束和审核展示；将被采纳网页的规范URL、正文哈希及规则版本纳入内容指纹，更新输入schema及提示词版本。仅刷新读取时间而正文未变不应重复推理。外部资料变化仍受任务代次、幂等和旧任务回写保护，构建只读已批准内容。抓取限制、重定向、超时、响应体积和公开网络目标约束也需测试。

当前只确认可行性，没有代码、表、后台开关或账户搜索验证；不能宣称现有模块已经能联网。
