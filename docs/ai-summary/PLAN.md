## 执行方式

一次仅执行一个步骤，完成后报告交付、实际测试、遗留问题和下一步，并更新本文件、STATE、MEMORY。等待用户继续指示再进入下一步。业务实施节点采用独立 PR，依赖节点使用堆叠 PR 并按顺序合并。先检查工作树并保留已有修改。

计划中的表名、文件名、模型和阈值为建议，步骤一确认契约后细化。生产迁移、资源操作、真实付费推理及部署按已有授权范围执行，权限不足时在相应步骤单独列出具体操作。资料不足属于正常结果，技术失败属于可重试结果，来源冲突进入人工复核。

## 来源信息不足的判定草案

步骤一交付为 [资料规则](SOURCE-RULES.md) 和 [固定样本](SOURCE-SAMPLES.md)，含 6 条历史资料及 19 条明确标记的构造案例。规则版本 source-policy-v1，样本版本 source-samples-v1。步骤二据此实现契约，模型效果仍待步骤四验证。

步骤二行为及语义审阅边界见 [CONTRACTS](CONTRACTS.md)，实际检查结果见 STATE。eligible 仅表示可尝试模型，语义充分性和冲突识别不属于确定性预检承诺。

步骤三实际迁移、任务恢复和模拟模型边界见 [TASKS](TASKS.md)。预算使用不可退款尝试账本按日聚合，公开表在后续批准/展示节点增加；此次不启动真实模型和生产资源。

步骤四真实结果见 [PILOT](PILOT.md)，接口见 [MODELS](MODELS.md)。用户明确确认付费 Workers 并缩减至 10–20 条来源，取代之前 120 条和 63 次提案。本轮取 12 条、尝试 18 次，冻结 Gemma + prompt-v2/params-v3，10 条最终结果均通过，保留旧版失败及两次未知送达。37 条库继续离线回归。队列接线与后台版本/预算配置一起在步骤五进行，当前继续停用，不进入灰度。独立 PR 继续堆叠不合并，合并前核验 Web 自动部署范围。

| 输入情况 | 期望处理 | 再处理条件 |
| --- | --- | --- |
| 仅名称、用户名、分类或标签 | skipped，原因 no_substantive_evidence，保留现有摘要 | 实质输入或规则版本变化 |
| 只有广告、联系方式、链接或表情 | 清理后复查，无实质资料则 skipped | 清理后的实质输入变化 |
| 简介明确、频道无公开帖子 | 可生成限于简介的短说明 | 简介变化或新增有用帖子 |
| 简介空、频道有明确公开帖子 | 可描述可见样本，使用“近期公开内容涉及”等范围限定 | 证据样本变化，或出现明确简介 |
| 群组简介模糊、无聊天样本 | skipped，不推断成员质量、讨论频率或活跃程度 | 简介补齐 |
| 机器人无明确功能说明 | skipped，不从名称、分类或启动参数猜功能 | 明确功能资料补齐 |
| 简介与帖子矛盾或歧义 | needs_review，原因 source_conflict，批准前用现有摘要 | 人工复核或来源变化 |
| 限流、超时或解析异常 | retry_wait，保留已有资料并有限退避 | 重试到期，耗尽后转 failed |

原因码在步骤一、二确认。任务执行状态与内容审核状态分开保存，needs_review 是候选审核状态。预检 skipped 不调用模型，模型返回 insufficient 时已产生的推理记录仍计入用量。人工可以补充独立摘要，但发布时需保留依据并遵守编辑锁定及审计规则。

## 共用验证要求

每个业务实施节点完成基础代码测试和源码审查，记录实际命令、结果和未验证事项。按当前改动执行相关检查。生产配置、模型价格与能力、PR 状态在行动前复核。人工截图或浏览器点验不能替代代码测试。

所有测试为待执行验收项。文档归档的链接检查不等同于业务测试、全仓源码逐行审计或生产验收。
