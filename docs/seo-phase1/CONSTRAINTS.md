# SEO 第一阶段约束

## 范围与授权

- 目标为 `/group/ai/`、`/rank/` 及对应 `/en/`、`/zh-hant/` 版本。
- 分类既有最新排序与分页路径须保持兼容，增强范围限于 AI 群组分类。共享组件通过可选参数启用，验证其他调用方。
- 2026-11-17 用户确认 AI 分类页节点并创建 PR，随后要求继续下一步。已确认该 PR 合并并完成部署点验，按计划继续排行榜节点并以独立 PR 交付。排行榜生产发布按后续明确授权执行。

## 实施要求

1. 复用现有组件、排序、筛选、快照、缓存与后台管理能力。
2. SEO 内容只能使用真实分类、标签、简介、统计、历史采样和可核实的算法口径。不得编造活跃度、推荐理由、成员增长、审核结果或官方关系。
3. 缺失数据与零值分别处理，不以缺失数据推断资源质量。
4. 重要内容与资源链接输出到服务端生成 HTML，保留 URL、Canonical、hreflang 和既有结构化数据类型与用途。结构化数据须与展示内容一致。
5. 三语言共用数据模型，新增说明分别本地化。繁体新增文案使用独立词条并检查最终构建结果，避免仅作机械替换。
6. 延续现有 UI，优先信息密度、可读性、移动端与键盘操作，不开展全站重设计。
7. 不使用 Durable Objects，不新增不必要的 Cloudflare 资源或请求链路。
8. 当前计划无 D1 变更。如实施发现真实依赖，先补充兼容旧数据、读写链路、迁移和回滚方案，说明新增范围后再推进依赖工作。
9. 保持条目数据、统计写入与榜单数值算法行为。仅修正展示、说明和已识别的默认榜一致性问题。
10. 兼容现有快照、Astro、Pagefind、Workers Assets 与 GitHub Actions 发布流程。

## 交付要求

- 节点一为 AI 分类页，节点二为排行榜，各自独立 PR。
- 测试、构建 HTML 检查与浏览器检查均记录实际结果。截图不能替代代码测试。
- 不把本地样例、代码静态审查、网页工具读取或成功部署写成生产数据正确性及搜索收录的证明。
- 每节点同步 PLAN、STATE、MEMORY，完成后列明剩余验证事项。
