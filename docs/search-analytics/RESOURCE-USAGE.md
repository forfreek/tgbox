## 日/月量级

- 每日10000个新身份事件：约19万–22万统计库写入行/日，按30天约570万–660万/月。
- 若主要为同身份同日重复：约11万写入行/日；新来源/语言维度或新词会增加记录。
- 签发1000个匿名会话：额外约6000写入行/日。签发预算与事件预算独立，合理调节防止批量身份创建。
- 规则较少时核心统计读取约每事件几十行；500条规则夹具约2054行，10000事件约2054万读取行/日。这是上限规则场景，不推断为典型生产值。
- 供应商验证最多一次/已预留token，独立日预算默认500、每身份3/分钟、每IP5/分钟；后台可在合理范围内调节日预算。
- 安全抽样每天最多100个样本，计数不携带关键词/身份，额外写入有限；被拒绝的抽样保留读取但不写入。
- API拒绝同样占Worker请求；边缘限流适配在阶段三实施，不能假称原生近似限流提供严格全球计数。
- 90天聚合行数取决于每日不同词/来源/语言组合；身份事实和receipt只保留8天，清理写入在阶段四测量。

正常负载不因旧免费额度而降低缓存或搜索体验。独立数据库隔离数据与查询故障，但账户级配额和Worker可用性仍共享；监控和部署参数按实际付费配置管理，不把库隔离宣传为账户级故障隔离。

Node本机规范化10000次约71.4ms墙钟，仅证明轻量字符归并；不是Workers CPU/冷启动保证。生产分地区CPU和网络延迟留待阶段六。

### 清理容量模型

B=有效事件预算、I=签发预算、V=验证预算、S=安全样本预算。按day清理identity_days上界4B；滚动expiry一个日常到期窗口会跨2个输入预算日，receipt上界2(B+I+V+S)，rate保守上界6B+2I+4V+16。minimumCleanupBatch=floor(max(三者)/900)+1，为最后探空留余量。默认(10000,10000,500,100)需92，现默认100合法；最高前三100000需1334，允许显式2000，不降低或静默改变业务预算。故障、多日积压、降低留存及无硬日上限的管理员日志不在日常模型保证内。

### 请求、KV与存储预算

成功搜索每候选最多1统计POST（挑战至多一次同ID重试，签发可合并），Bot统计复用webhook请求和结果；前端不轮询。每日10000新身份事件按19–22已知写/事件约570–660万写/月，若全为全新匿名会话再加约180万已知写/月，清理/安全/挑战/运维另计。最高100000预算将该事件部分放大10倍；用户自行设置，不自动提高线上额度。

公开榜单P次成功打开/月≈P Worker请求+P KV读+2P主库singleton查询；原生拒绝0D1/0KV，但仍有Worker请求。Cron约30/月，每次成功发布1 KV写+1读回，人工/审核刷新另加；不可变key8天TTL可重建，无逐事件KV计数。曾生成内容不足8KB，不发布身份、IP或完整统计。

最多日聚合行B×90：默认90万、最高900万，另有8日身份/短期receipt/rate及索引。64字UTF-8/display双字段及索引会影响字节体积，最高预算可能逼近单D1 10GB；不能用行数当固定存储大小。提高预算前测实际bytes/row与清理，建议监测70%预警、90%人工处理；不自动缩短90天保留、不删库，不设置影响核心业务的账户全局kill开关。
