# 架构决策记录

日期：2026-11-28。状态：下述基础决策已确认；具体实现须通过阶段验收。

## ADR-001：独立统计数据库与共享模块

D1 为唯一可信源；统计迁移与核心迁移分离。入口依赖 search-analytics，后者不依赖 apps/core。核心 FTS 复核通过注入回调适配，避免共享包反向依赖核心业务层。事件写入只抽象一个轻量 writer 接口，当前 D1 实现；不引入 DO/Queues。

## ADR-002：严格撤回优先于只读 KV

用户确认公开榜单请求可增加统计 D1 版本校验。使用主库，不采用 replica 旧读或持久审核缓存。KV payload 含 generation/rulesRevision/configVersion；与 D1 不符时空榜，不用 previous 或推荐绕过。响应不得允许无需服务端审核检查的陈旧 HTTP/客户端缓存复用。不能撤回已经显示在浏览器中的内容；语义是审核提交后的新服务端读取不得返回旧审核版本，审核与读取重叠时以权威检查的线性化点为界。

## ADR-003：客户端结果不作为证明

用户确认对客户端手动、有结果的榜单候选追加服务器 FTS 复核。Pagefind 决定用户看到的结果，FTS 仅决定能否增加榜单贡献。计数明确区分 client_reported_result 与 verified_result；差异可观测，不声称两引擎完全等价。Bot 结果由服务器查询确定。

## ADR-004：身份与幂等

Telegram 域 HMAC 对 Mini App/Bot 一致，匿名会话随机 ID 使用另一域。标识稳定性覆盖排名窗口，密钥版本显式标注；轮换会使窗口身份不可比，需暂停/清空可重建身份贡献并重新冷启动。请求 receipt 只存 HMAC event key 与安全 payload digest，不存逐次搜索正文/IP/凭证。receipt、限额和 daily identity/stats 同一事务提交。

## ADR-005：排名与数据口径

北京时间昨日结束的最近 7 个完整日。每个 keyword/identity 先 MAX(eligible_day)，再按年龄 1、2–3、4–7 日赋 1.0、0.6、0.3；门槛按窗口唯一身份，不按每日身份相加。相同得分再按独立身份、规范化关键词稳定排序。source/locale 维度用于分析，不再次重复全球身份贡献。

## ADR-006：发布栅栏

不可变 KV generation key 写入并校验后，在 D1 执行带 lease token、revision/configVersion 的 CAS 发布。别名 global/previous 仅兼容或诊断，公开入口以 D1 指针为准。发布失败保留上一份正常权威指针；若审核已变更则旧指针不再可展示。previous 仅能在仍通过当前审核/配置版本时使用。清理分批，任务日志记录失败阶段。

## ADR-007：安全指标不能放大攻击

精确的成功/幂等计数来自已接受事务；拒绝原因优先 Workers 聚合指标或固定码采样。后台明确标注样本与估算，不能将未逐条持久化的拒绝显示成精确总数。采样也须设每日写入预算与固定维度，不按恶意关键词/身份建无限计数键。

## ADR-008：付费容量与合理防刷

2026-11-28用户确认付费版，不采用免费额度刻意限制功能。全局事件默认10000/日保持，后台范围放宽至100000；签发/验证日预算同上限，个人/IP额仍用于防滥用。没有自动改线上阈值。资源实测用于容量监控，不作为未同意的降额依据。独立库不承诺隔离账户整体故障。

## ADR-009：发布快照与清理独立性（阶段四）

指针和私有排名快照同D1事务，不把分数/身份数放进公开KV。public读的两次检查各新建first-primary会话，不用bookmark会话的后续副本查询代替主库检查。公开接口no-store，版本未知时空榜。部署展示开关、D1 publication与jobs分离，关闭展示仍可清理。清理一轮为原子续租及9个固定表的guarded DELETE，按付费D1绑定API上限留收尾余量；时间/容量耗尽明确失败并可重复排空。

## ADR-Admin：复用认证、事务审计与任务边界（2026-11-28）

采用既有adminMiddleware与精确Origin POST保护，访问层集中在共享包，UI只调用版本化server fn。使用已部署SETTINGS_KEY的独立HMAC域作为审计主体，避免为Admin索取采集身份Secret，避免在统计库持久化原始管理员TG/邮箱。审计必须与业务CAS同一事务；核心审计和独立统计库无法跨库事务，故审计写在独立统计库，不双写伪造原子性。

列表资格得分与发布共用ranking.ts，不复制权重算法；私有已发布分数来自0003快照。关键词100条分页按80词分段复核以遵守D1每SQL100绑定参数限制。审核先失效，再best-effort后台刷新；手动刷新await整个任务给出最终状态，避免把HTTP waitUntil当90秒可靠执行器。不追溯恢复未具资格贡献，未来若需要审核后追补必须先保存可验证的独立资格事实，不能从聚合推算。

平台证据：[D1事务与会话](https://developers.cloudflare.com/d1/worker-api/d1-database/)、[D1限制](https://developers.cloudflare.com/d1/platform/limits/)。

## ADR-验收：删除未审核回退，按词审核与清理容量（2026-11-28）

删除静态推荐prop/构建计算，关闭和异常空榜；保留已有UI及搜索引擎。禁止回滚到不具撤回保护的旧前端，已有屏幕不可擦除。新SQL先保留latest身份权重，再MATERIALIZED分组审核，谓词只依赖keyword故等价，LIMIT仍在审核后；无新索引。NFKC后复查相同安全规则。

最大预算不能配结构不足的清理批。采用可解释的跨字段模型+2000上限，不限为免费额度，不自动改管理员预算；旧实验配置不静默迁移。实际多地区吞吐、SQL30秒/总90秒与历史积压仍受Runbook控制，不假称精确TTL或可靠队列。
