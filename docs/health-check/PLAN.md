# 资源健康检查实施计划

2026-11-27，Asia/Shanghai。用户授权按阶段实施；覆盖频道/群组误判隐藏与机器人身份/功能验证，统一证据模型、按类型制定规则。生产迁移、历史数据修复和部署另须明确授权。

## 阶段一：纠正弱信号与隔离头像任务

- 已有条目View/Contact占位页记unknown，不累计失败；新收录继续原身份校验，不把unknown视作批准。
- 正常频道主页不被/s/预览重定向推翻；移除previewRedirected判定入口及旧回归预期。
- 缺头像优先通道仅写头像及必要的版本/更新时间/发布dirty，不写简介、统计、帖子、存活状态，不累计失败、不隐藏、不恢复、不发失效通知。复用现有租约、双游标和预算。
- 机器人无头像、无月活但Start Bot可识别时保持身份可识别；这不表示功能验证通过。
- 验收：Telegram解析/快照、core及bot回归和类型检查；独立PR及Linux CI。不得把本阶段称为整个健康检查完成。

## 阶段二：统一证据、策略和后台解释

依赖阶段一。

- 先形成契约：公开可访问性、检查结果、发布状态分离；机器人功能验证单独记录动作、时间、范围与结果，未验证不冒充功能正常。
- 持久化精简证据：来源、观察时间、HTTP/重定向/解析原因、规则版本；制定保留上限、清理和索引，避免无限HTML与全表扫描。
- 统一策略入口覆盖Cron、手动刷新、收录、审核和通知。不同失败原因不混计；重复观测去重、过期证据失效、并发乱序保护；成功证据清理旧异常。来源异常采用退避/熔断，不能用同批失败不足2条证明来源健康。
- 类型变化进入复核；仅网页弱信号不自动隐藏。明确充分证据清单，目前没有充分证据的路径不能产生自动隐藏。移除阶段一仍保留的旧类型变化隐藏策略与新收录banned措辞。
- UI和通知显示待核验与可追溯原因，不再将网页异常显示为确定封禁。不引入用户账号探测或强制新增外部服务，不向其他机器人自动发送/start。
- 迁移前列清旧liveness/fail_count/first_fail_at/last_fail_at及所有读写方，定义短期兼容、最终唯一事实来源、切换和删除条件；不得无限保留两套策略。
- 验收：状态机/幂等/乱序/来源故障/人工保护/预算测试；后台实际呈现及迁移/回滚演练；独立堆叠PR。运行时或界面实现前按需读取相关技能。

## 阶段三：历史误判复核与数据修复

依赖阶段二。

- 重新只读导出当前系统隐藏与异常条目；此前12条仅为11-27排查快照，不可当成固定名单。
- 形成可审核清单：确认有效、确认不可用、无法确认、身份/类型变化；记录独立证据与时间。不能用同名URL自动判断身份未变化。
- 明确授权后按条件更新、幂等执行并记录前后值；仅恢复有证据支持的系统误隐藏，不覆盖人工隐藏/移除；旧失败计数标注来源并停止参与新策略。
- 验收逐条状态、审计、构建发布及网站展示；不盲目恢复全部、不以缓存搜索结果代替实时验证；独立PR记录实际证据和未确认项。

## 阶段四：生产验收与清理

依赖前述节点；本专题关闭门槛。

- 经授权按迁移/Worker/Admin/Web依赖顺序发布；先观察新判定与人工样本对照，再验收发布状态变化。观察须覆盖两种刷新通道及至少一轮常规扫描；确认真实周期，不预设一天内轮完。
- 检查已确认有效样本是否误隐藏、异常原因分布、复核积压、请求/读写预算及来源熔断。未知样本不纳入“已验证无误”结论，不能承诺全站零误判。
- 删除旧策略、无用分支、兼容字段/读写与通知；若回滚窗口需要保留字段，明确到期条件及删除migration，全部清理前不得标记专题完成。
- 完成文档、测试、运行证据和回滚；回滚不得恢复已知会误隐藏的旧行为，应保留安全判定。独立PR，最终审查所有入口只使用一套策略。
