# 简介与 AI 链路核验

## 2026-11-15 核查范围

沿用 programmatic-seo 的来源、独有价值与批量模板检查，以及 seo-content 的准确性、人工增值和输入证据检查。技能版本见 VERIFICATION.md。

读取公开 `/data/entries.json`，取得 1,913 个条目。按类型各抽 10 个，覆盖中文、已有中文译文的英文、其他语言、最短与最长简介，去重后共 30 个。这是目的性抽样，样本错误比例不能推算全站。

实际请求样本的中文与英文详情页共 60 页，全部返回 200。公开 JSON、抽样、正文与检查结果位于 evidence 下对应 public-entries、sample-selection、sample-pages、sample-audit 文件。数据快照与页面采集存在时间差。

lang 根据标题、简介及最近消息共同检测，代表条目内容语言，不能直接视作简介文本语言。没有译文不等于调用失败，可能来自队列、长度限制、原文语言和处理进度等因素。

## 已核实的数据流

1. 收录从 Telegram profile.description 写入原简介。开放导入 PR #19 会合并 Telegram 简介与来源列表说明。
2. Workers AI 分类器输出分类 slug，导入 AI 另做质量判断。已核查路径没有原创编辑简介生成器。
3. hourly maintenance 使用 `@cf/meta/m2m100-1.2b`，向模型传 text、source_lang、target_lang，生成另一语言译文。当前每次最多 8 条，实际受共享维护预算限制。
4. 英文、中文以外的语言回退到是否含汉字判断。俄语、阿拉伯语等不含汉字文本被作为英语输入。日语含汉字文本可能被作为中文输入。
5. 模型返回非空文本后直接存储，目前未见用户名、链接、重复输出和语义质量校验。
6. 页面优先取对应语言译文，否则显示原简介。entrySummary 把名称、分类、人数、创建时间和活跃度拼成固定句式。metadata 将模板摘要放在简介之前再截断。
7. 刷新以 Telegram 原文更新 description。updateEntryCold 在原简介变化时清除双语译文。后台现有编辑函数主要处理分类、标签、状态等，本轮未发现独立的编辑简介保存路径。

## 具体问题与证据

### 第三语言路由错误

telegramtipsar 的 lang 为 ar，原文是阿拉伯语，已有中文译文重复“广播电台”。中文详情页实际展示该译文。源码把此类输入的 source_lang 设置为 en，构成直接可定位的语言路由问题。

https://tgsearch.app/detail/telegramtipsar/

### 用户名改变或信息遗漏

testflightcn 原文的 @zaihua_ad_bot 在公开英文译文中变为 @zuaaih_ad_bot。zxfast 的 @zxfast_channel 变为 @zfastx_channel，另有联系方式遗漏。30 个样本中 14 个有译文，4 个被受保护 token 检查标记为遗漏或变化，其中遗漏需要人工结合语义确认。字符串检查不代表每项都是错误链接。

https://tgsearch.app/en/detail/testflightcn/

https://tgsearch.app/en/detail/zxfast/

### 原始资料缺失与模板重复

cocoon、customnotificationsounds 等样本原简介为空。翻译模型缺少可翻译材料。其页面仍能输出事实模板摘要，但没有由此增加条目用途、适用人群和使用限制等信息。填充这些内容需要额外可核验输入。

https://tgsearch.app/detail/cocoon/

### metadata 的条目含义被模板挤占

样本 metadata 经常在人数、日期、活跃度等模板字段处截断。长名称更容易占满预算，条目用途尚未出现。这个问题可通过摘要优先级与模板处理，不依赖更换模型。

### 编辑与刷新边界

直接把生成的编辑文案放入原 description，会在 Telegram 原文不同时被刷新更新。新增编辑内容需要明确存储、版本、失效与人工覆盖关系。可先复用现有数据与页面接口设计最小变更方案，具体是否需要新增字段需在实现设计时确认。

- `pnpm --filter @tgbox/db exec vitest run src/translations.test.ts --maxWorkers 1`，5/5 通过，覆盖原文变化清除译文等行为。
- `pnpm --filter @tgbox/bot exec vitest run test/bot/translations.test.ts --maxWorkers 1`，12/12 通过。AI 被测试 harness 模拟，验证调度、参数、回退和重试，不代表真实模型质量。
- 现有 translationSource 测试明确把俄语回退到 en、日语含汉字回退到 zh。现有测试通过与错误质量样本可以同时存在，修复需修改对应预期及补充回归范围。
- 当前进程没有 CLOUDFLARE_API_TOKEN/ACCOUNT_ID，仓库导入脚本使用的默认 Wrangler OAuth 配置路径也不存在。尚未执行真实模型 A/B 调用，没有模型质量或延迟对比结论。

## 模型候选与验证设计

官方目录仍提供 m2m100-1.2b 翻译模型，也提供项目已使用的 gemma-4-26b-a4b-it 文本生成模型。后者可作为候选，实际能力需要同输入测试确认。

https://developers.cloudflare.com/workers-ai/models/m2m100-1.2b/

https://developers.cloudflare.com/workers-ai/models/gemma-4-26b-a4b-it/

模型对比需至少包含三组，区分语言路由修正与模型更换带来的影响。

- 当前 m2m100 参数行为，作为基线。
- 相同模型配正确源语言及用户名、链接保护，评估链路修正的收益。
- 候选文本生成模型配同等源资料与保护规则，评估翻译和事实整理。

优先选择阿拉伯语重复、中文用户名变形、多语言混排、短简介、广告较多和空简介等样本。评估事实一致、标识保留、语言正确、重复、拒绝无依据补写、耗时和 token 用量。空简介应呈现资料不足的结果。所有模型输出先记录到审查样本，待核验后再决定上线逻辑。

## 根据证据形成的实施顺序建议

1. 内容线先处理高重合指南，补充有依据的本站示例与筛选方法，并对照来源核实继承的事实性表述。首页进一步审查本站用途和内容组织，避免用不同条目列表直接等同于编辑增值。
2. 简介线优先修正语言识别、标识保护和输出校验，调整 metadata 的信息优先级。
3. 取得真实模型对比结果后决定是否切换翻译模型、是否增加事实整理步骤。原创编辑内容的存储与刷新设计同步明确。
4. 先形成小批样板，再处理既有数据。模型重试、缓存身份、版本及人工覆盖应随最小实现一起验证。

现有证据支持内容与生成链路需要调整。AdSense 当前仍为用户报告的“正在准备”，上述问题与等待时间的因果关系尚未证实。
