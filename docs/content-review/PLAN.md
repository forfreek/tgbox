# 内容优化与 AI 简介审查计划

## 目标与范围

提高 TGsearch 相对上游的内容价值、信息准确性和可维护性，沿用现有架构。首页已收录，AdSense 审核中。Bot Fight 相关排除在本项范围外。

当前阶段为证据核验。先验证内容差异度与简介生成链路，再决定具体修改计划和实施范围。页面重建需要具体证据，整体架构维持当前方案。

## 核验门槛

- 用户确认 2026-11-10 提交，当前状态“正在准备”。以审核中记录，避免将等待时间解释为拒审或认定已有审核失败原因。
- 优先核验内容差异度假设，同时记录支持证据、限制与可反驳该假设的观察。
- 完成线上正文与上游对照、简介字段读写追踪后，再据证据制定修改方案。
- 修改范围应逐项引用核验报告。当前后续阶段仅为候选工作，尚未确定具体改写及链路改造内容。

## 技能组合

- `coreyhaines31/marketingskills` 的 seo-audit、programmatic-seo、content-strategy，分别用于索引信号、目录模板质量和内容规划。
- `AgriciDaniel/claude-seo` 的 seo-content，用于内容来源、信息增量及可信度交叉检查。
- `addyosmani/web-quality-skills` 的 web-quality-audit，用于修改后的实际渲染与使用体验验证。
- 实施前按所需技能读取完整入口和相关引用，记录 commit 与适用章节。当前已查阅相关技能入口片段，尚未安装。
- 发布商审核相关结论对应 Google 官方政策，记录页面证据与判断依据。

## 分阶段待办

### 1. 基线与内容清单

- 核对实际生产版本、最新 main 和未合并改动，列出拟修改文件交叉。
- 按首页、关于页、指南、分类、标签、详情页列出内容来源、用途、语言和维护方式。
- 对比上游正文，区分公共模板、引用来源、本站新增信息，保留来源与开源署名。
- 全量可获取文本做重复筛查，按页面类型抽样核查，记录抽样范围和覆盖限制。

### 2. AI 与简介数据流

- 追踪收录、批量导入、管理员编辑、定时刷新、翻译、摘要和详情页展示的完整读写路径。
- 查找未合并分支是否存在另外的简介生成器，明确原始简介、翻译和模板摘要的字段边界。
- 检查输入来源、语言识别、模型与提示词、输出校验、链接与广告噪声、事实依据。
- 检查失败重试、预算、缓存、源文变化后的译文失效，以及刷新是否覆盖人工内容。
- 评估既有条目的兼容与处理方式，历史数据重生成应先形成可复核样本及回退方案。
- 抽样关注空简介、短简介、多语言、广告较多、过期信息及翻译失真的条目。

### 3. 内容方案与样板

- 先形成首页、单篇指南和单个详情页的修改样板，明确每处新增信息的来源。
- 目录内容考虑筛选标准、数据更新时间、统计口径、使用限制和有依据的编辑说明。
- 中英及繁体逐项检查准确性、阅读体验、链接与页面事实的一致性。
- 复核关于、联系方式、隐私说明、收录和推广规则是否符合实际运营。
- 以事实覆盖和任务完成度验收，避免靠同义替换或字数目标制造差异。

### 4. 实施与复验

- 在最新 main 的独立工作树实施，每个交付节点独立 PR。依赖明确时使用堆叠 PR。
- 对受影响路径运行现有相关测试、类型检查和构建检查，并核对实际页面渲染。
- 检查 canonical、hreflang、Sitemap、索引规则和正文是否一致。
- 记录效果基线及复验结果。审核结果与搜索表现需要独立观察，避免将内容修改归因为审核通过保证。

## 每项问题的记录字段

页面或代码路径、输入与输出样例、证据来源、影响范围、优先级、建议、修改分支、验证方法、当前状态。
