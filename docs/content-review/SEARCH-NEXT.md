## 技能应用

- seo-audit 用于搜索结果标题、摘要与页面内容的对应检查。
- programmatic-seo 用于检查详情模板对批量条目的信息增量。
- seo-content 用于核实简介事实、来源、翻译与实际可用性。
- 内容样板延续已确认的 content-strategy 方法，以用户具体任务及可核实信息为依据。
- 实施前按需读取对应技能与源码，沿用现有架构，排除 Bot Fight。

## 节点 A 详情摘要与三个条目样板

目标为让访客在搜索结果与详情页看到条目用途及可核查信息。

1. 对照三个候选条目的原始公开资料、本站描述及上游，确认功能、入口、使用条件及资料缺口。
2. 调整标题用户名去重与 metadata 内容优先级，避免人数和日期挤占功能说明。保留字段缺失回退。
3. 先形成中英及繁体样板，检查正文、标题、摘要和链接一致性。信息不足时明确缺口，新增评价需要来源。
4. 用前期 30 条样本验证模板适用性、空简介、长标题及多语言兼容，复跑构建集成测试与内部链接检查，覆盖移动端阅读。
5. 独立 PR 交付，记录样板及验收结果。当前不据一天数据给出点击增长承诺。

## 节点 B AI 翻译链路与模型评测

1. 修正简介语言路由，保护用户名和 URL，验证重复及失真输出。
2. 核对原始资料、译文和编辑内容的存储及刷新边界，避免覆盖人工编辑。
3. 用相同样本比较现有参数、修正输入后的现有模型、候选生成模型。衡量准确性、标识保留、无依据补写、延迟与成本。
4. 当前运行环境缺少已核实的 Cloudflare 调用凭据，真实 A/B 尚未执行。候选模型通过评测后再决定切换。
5. 批量重处理前先形成可复核样本、版本记录及恢复方案。

## 节点 C 分类、首页与剩余指南

优先复核 AI 频道、视频频道及频道入口等已有搜索展示的页面，补充经过验证的选择标准与用途说明。首页围绕品牌、服务范围及导航组织完善内容。其余指南沿用 #40 的事实与来源标准，按范围逐项交付。

## 效果复验

以 7 天、28 天导出补充基线。需要重点页面的查询明细，才能核对实际查询与落地页匹配。记录部署日期、Google 抓取后标题摘要、相同 URL 与查询的展示和点击变化。综合语言、设备和地区分布，单独观察英文泛词与中文实体词，避免用少量点击得出稳定转化结论。

Search Console 的自然搜索表现用于内容优先级与后续效果观察，AdSense 当前审核状态及具体问题仍需独立核实。
