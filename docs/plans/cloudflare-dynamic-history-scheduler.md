## 调度协议

`public_history_recovery_enabled` 默认为缺失，只有值为 `1` 才执行恢复。公开投影未 ready 时返回 `not_ready`。
`public_history_recovery_cursor` 记录本轮上一个已让出轮次的 entry ID。每次通过
`SELECT id FROM entries WHERE id>? ORDER BY id LIMIT 1` 选择一个条目，EXPLAIN 命中 INTEGER PRIMARY KEY。

`clean`、`write`、`verify` 保持游标，在后续 tick 继续该条目。每批最多处理 100 点。
`ready`、`invalid`、`oversized`、条目已删除或本次失败均让出轮次，通过 CAS 提交游标。
到目录末尾重置为 `0`，下一轮重新核验 R2 对象。不同调用句柄和 Worker 重启沿用 D1 进度。
重复或并发 tick 的镜像写入继续由 generation/source revision/身份条件保护。

定期恢复允许超限和失败条目让出轮次，以便处理其他条目；严格回填工具仍会在超限时阻塞，并保留完整审计门禁。
本恢复游标用于循环巡检。全量一致性验收继续使用独立回填/审计流程。
损坏游标从 `0` 恢复，失败对象保留显式状态并在下一轮重试。

## 预算与公平性

沿用现有 50 次保守预算。恢复任务预留 16 次 SQL/R2 操作，不足时直接返回 `budget`，执行 I/O 为 0。
默认关闭或未 ready 时消耗一次固定键 D1 状态读取。异常路径返回完整预留数，后续任务据此判断余额。

USDT、广播和既有刷新先执行。历史恢复与推广准备按五分钟 tick 奇偶交换先后，
每个任务的 `reserved` 加入下一任务的 `spent`。预算边界测试确认 spent=34 时，历史先执行将下一项预算推进至50；
推广先执行将历史的预算推进至44，历史跳过该 tick。

| 本地路径 | SQL 语句与 R2 操作合计 |
|---|---:|
| 初始化 clean | 11 |
| 清理并进入 write | 11 |
| 空历史 write 到 verify | 10 |
| verify 后 R2 复核失败并失效 | 16 |

测试将 batch 内每条 SQL 单独计数，预算覆盖版本门禁、事务、R2 前后复核和故障后失效。
逻辑预算高于部分 D1 batch 的 RPC 数量，Paid rows-read/rows-written、CPU 和延迟仍需隔离环境复测。
每次 I/O 有界，完整巡检轮次随条目数、历史大小和空闲预算增长。既有任务持续占满预算时恢复可能延迟。
启用前应记录实际 `budget` 比例和整轮时长，不能用巡检周期承诺实时更新时限。

保留镜像表、恢复游标和原始 R2 对象。重新启用后从持久化阶段续跑，游标也可在受控操作中重置为 `0`。
