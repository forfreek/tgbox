# 刷新历史写入一致性

本节点承接 PR #37，独立分支为 `codex/cloudflare-history-write`，对应 P1-7 历史写入同步子任务。
Phase 1 当前 5/8，总计划 12/55。四榜投影、完整历史审计和预发布验证继续验收。

## 问题与协议

写前版本递增后，并发镜像仍可能读取旧 R2 并重新发布。为覆盖这个窗口，migration 0027 增加
`history_writes`，每个条目最多一条待完成意图，保存 username/listedAt、随机 token、原 ETag 和待追加的时间/成员数。
主键为 entry_id，新增二级索引数量为 0。

1. 新增意图在同一 D1 事务中将旧镜像设为 stale 并递增公开 revision。
2. 镜像初始化、每批提交和公开基准查询均在 SQL 内拒绝有意图的条目。
3. R2 在原 ETag 匹配时追加持久化意图中的点。缺失对象采用仅创建条件，保存 token 到 customMetadata。
4. R2 已有相同 token 时直接确认完成。条件失败时保留意图，以后重新读取判断。
5. 仅删除匹配 token 和当前条目身份的意图。删除触发器再次失效镜像并递增最新 revision，随后镜像从新对象重建。

Cloudflare R2 的条件检查和对象写入原子执行，条件失败返回 null。绑定读取直接访问存储。
实现基于已核对的官方语义，并通过本地 workerd 测试，真实远端故障时序仍需预发布演练。
[Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)、[一致性模型](https://developers.cloudflare.com/r2/reference/consistency/)

意图包含可重放的完整采样点，重试不会使用新的成员数或新时间替换未完成点。
成功追加会改变内容 ETag，延迟的相同意图重放无法覆盖后续追加。
意图使用明确完成证明解除，恢复过程可跨 Worker 重启。

`public_history_writes_enabled` 默认缺失，值为 `1` 时创建新意图，另需公开投影 enabled/ready。
关闭新写入后，既有意图仍由新版刷新和恢复任务处理。恢复功能使用 #37 的独立开关。
未采用新链路的正常请求继续走既有周采样规则。R2 JSON 数组、键名、HTTP metadata、公开 URL、
Bot/Admin 审计和现有代码/内容构建入口沿用原实现。
完成意图时保留 `dirty_since`，使用数据库完成时钟，支持恢复后继续由既有构建调度发现变化。

## 故障与公开状态

| 情况 | 行为 |
|---|---|
| D1 创建意图失败 | R2 保持原值 |
| 意图已创建、R2 put 前终止 | 下一次恢复读取原 ETag 并追加同一个采样点 |
| put 成功、D1 完成失败 | 通过 R2 token 确认并完成，避免重复追加 |
| get 后对象被替换 | 条件 put 返回 null，意图保留，原对象不被覆盖 |
| R2 已被外部或旧实现改写且 token 不匹配 | 报 source conflict，保留意图和公开门禁，等待核对 |
| 镜像读取版本后出现新意图 | 源 revision 及 SQL 意图门禁拒绝旧结果发布 |
| 旧完成回调晚到 | token 不匹配时无法删除当前意图 |
| 删除/改名/listedAt 变化 | 源事务清理该身份的意图和镜像，旧完成回调无法提交 |

下架仍由查询中的实时 approved 条件控制。R2 保留既有 username 键，生命周期变更时的在途请求
仍可能完成对旧键的写入，D1 会拒绝旧身份提交。旧键清理及同 username 再收录的历史继承策略继续随完整审计验收。
公开排行接入前还需验证所有实际读取消费者和缓存门禁。

单源处理沿用镜像的 1 MiB/4096 点预算，达到追加上限时在创建意图前失败。
超限历史的专门处理路径仍为 **待验证**。结构错误沿用旧刷新空历史回退口径。

## 迁移、部署与回滚

1. 逐项获得预发布操作授权后应用 migration 0027。新代码即使新写入开关关闭，也依赖该表。
2. 部署新版 Bot/Admin。验证旧版本及开关关闭时在途历史写入已结束，再开启新写入链路。
3. 开启已验收的恢复调度，验证故障补偿、冲突告警、全部待完成意图和镜像状态。
4. 对照原 JSON、采样口径及构建输出，记录真实 R2 条件写入、触发器费用、CPU、延迟和调度整轮时间。
5. 完成后再按单独授权安排生产迁移、应用发布及开关启用。

本节点只生成并在本地隔离库应用 0027，生产环境操作为0。沿用原 Worker/D1/R2/Cron 和资源绑定。

回滚先关闭新意图创建，保留新版恢复，确认所有意图完成且在途条件写入已结束，再回退到 #37。
在已授权环境可以用以下定向查询检查目标条目或按主键分页检查待处理意图。

```sql
SELECT * FROM history_writes WHERE entry_id = ?;
SELECT * FROM history_writes WHERE entry_id > ? ORDER BY entry_id LIMIT 100;
```

外部源冲突需人工核对现有 R2 历史、备份和意图后处理，操作需单独授权。禁止以超时删除意图来绕过门禁。
若无法安全处理冲突，保持该条目派生读取受阻，继续使用支持意图门禁的新版代码。
表和触发器保留，避免旧应用源写入引用缺表。后续再启用前重新验证意图与镜像完整性。
