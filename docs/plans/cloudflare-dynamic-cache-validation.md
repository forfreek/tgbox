# P1-6 缓存时间与并发失效验收

本交付节点承接 #27，属于 P1-6 的缓存协议子任务。P1-6 整项继续待验收，Phase 1 保持 5/8，总计划 12/55。

## 审查发现与修正

`packages/db/src/public-cache.ts` 原先在 cache.put 前校验内容版本。put 内等待期间发生下架时，调用方可能得到校验前的值。
原先对 validUntil 的检查只影响缓存写入，loader 完成或缓存读取后的响应可能已跨过推广自然过期边界。

- [x] 将最终权威版本检查放到缓存 I/O 完成后，命中和回源各保留两次版本查询。
- [x] 返回前校验整个有效区间，超时、自然过期及向后跨界的时钟变化返回明确的 retry 错误。
- [x] envelope 增加 validFrom，缓存协议键升级 tgbox-public-v2，避免旧数据缺失区间约束。
- [x] maxAgeMs 从本次读取开始计时，loader或缓存延迟消耗同一寿命预算。validUntil 必须为安全整数毫秒，缺省时由maxAgeMs约束。
- [x] 缓存故障继续回源，缓存写入故障仍执行最终状态/时间校验。已写入的旧值被旧revision键隔离。

这是以最后一次D1读取为一致性检查点的响应协议。写入完成后的新请求读取新版本，已开始的并发请求依照最终检查点决定成功或重试。HTTP自动重试次数和映射继续在Phase 2接入时验收。

## 测试与性能口径

新增测试使用真实本地D1，在cache.get/cache.put中执行下架，验证读取拒绝发布旧版本。
时钟测试覆盖慢put跨过validUntil、命中值parse后过期、时钟回退、未来区间缓存回源和非法时间边界。
原有过期测试改为要求loader产生的已过期结果返回错误，避免把TTL写入判断当作响应有效性保证。

成本测试捕获实际详情缓存读取SQL与参数，重放每条 SELECT 的 EXPLAIN 和D1 meta。
缓存命中只允许两条权威查询，回源四条包含详情和标签查询，均断言使用索引、无SCAN且rows_written=0。
命中预算最多12 rows-read，回源预算最多30 rows-read。该样本使用单个已审核条目且无标签，实测命中12行、回源16行。
它覆盖完整缓存调用的D1查询，缓存网络请求、CPU、字节数及多地区延迟仍待部署等价环境测量。

## 缓存依赖与回滚

缓存键沿用协议、内容revision及调用方keyParts，页面维度遵守 `cloudflare-dynamic-contracts.md`。
调用方负责涵盖locale、范围、排序、分页和详情username，涉及推广/排行时提供正确validUntil。
内容、状态、翻译、分类标签、隐藏与R2的全部写入覆盖继续在P1-7验收。
实际Cache/KV adapter、请求内校验复用和生产规模预算仍待Phase 2/P1-6后续节点完成，整阶段切换前必须验收。

应用回退可revert本节点提交，缓存读取随协议键切回对应版本。未来发生过生产内容写入或权威恢复时，回退版本须使用新的缓存命名空间并验证公开状态，避免命中旧部署数据。
本节点通过本地测试与独立PR交付，生产资源操作为0。后续阶段需要迁移或部署时按专项授权执行。
