打开一个频道详情页，你可能同时看到成员数、近 7 天变化、近 30 天变化、活跃度和最近消息。要利用这些信息作选择，可以先确定每个字段回答的问题，再把观察日期记下来。

本文按照 TGsearch 当前页面和数据处理方式，整理一份读数方法。演算表使用假设数字，方便你复现计算。

## 先分清你正在读哪个指标

| 页面信息 | 读数时关注什么 | 可以补充检查什么 |
| --- | --- | --- |
| 频道订阅或群组成员 | 当前目录记录的规模 | Telegram 原始页面上的当前人数 |
| 机器人月活用户 | 按字段标签理解使用规模 | 功能是否符合用途、入口是否可用 |
| 成员趋势 | 起止日期、采样数量和变化方向 | 同期发布内容与传播活动 |
| 活跃度 | 页面展示的活跃分档 | 最近消息的日期和实际内容 |
| 最近消息阅读量 | 帖子发布时间和观察时间 | 转发来源、消息类型及上下文 |

先通过[频道目录](/channel/)找到候选，进入详情页后再填写这些信息。需要观察多个条目时，可以把它们放进同一份记录表。

## 用一组数字理解增加量与增长率

下面假设两个频道都在同一个 7 天观察窗口内取得了起点和终点记录。

| 演算频道 | 起点人数 | 终点人数 | 增加量 | 按起点计算的增长率 |
| --- | ---: | ---: | ---: | ---: |
| A | 1,000 | 1,100 | 100 | 10% |
| B | 10,000 | 10,100 | 100 | 1% |

增加量的计算是“终点人数减去起点人数”。增长率再将增加量除以起点人数。对 A 来说，`(1,100 - 1,000) / 1,000 = 10%`。

如果你希望观察近期新增关注，先记录增加量。如果你关心变化相对原有规模有多大，再补充增长率。起点为零或未知时，应先保留这个信息缺口。

## 给每次比较写上观察窗口

TGsearch 的详情趋势根据已记录的采样计算周期变化。页面取最新记录作为终点，寻找达到相应周期之前的历史记录作为起点，因此实际起点可能早于恰好 7 天或 30 天的位置。

比较两个条目时，检查它们各自的历史范围。一个刚开始积累数据的条目和一个已有多次采样的条目，能够支持的观察长度会有差别。图形出现明显变化时，进一步查看对应日期和采样间隔，再解释它的含义。

### 趋势暂时缺数据时

先记录“当前人数”和“尚缺某周期历史”，之后再回来复查。可以同时阅读近期消息，确认内容主题、更新节奏和原始链接。如果缺少起点，单凭当前人数无法完成周期增长计算。

## 把阅读量放回帖子上下文

对几条发布时间接近的帖子，记下观察时间、内容类型和阅读量。教程、公告和短消息各有用途，比较时保留这些区别。

Telegram 官方说明，频道阅读数包含转发副本的阅读，计数属于近似值，间隔一段时间后的再次访问也可能产生新计数。阅读数适合与发布时间、转发情况一起观察。[Telegram 阅读计数说明](https://telegram.org/faq_channels)

遇到人数变化时，可以继续核对同期是否发布了重要内容、开展了活动或获得了传播。把能确认的事件和仍需核实的解释分别记下，逐次积累依据。

## 建立自己的复查记录

| 记录项 | 建议填写内容 |
| --- | --- |
| 观察对象 | 用户名、TGsearch 详情页链接 |
| 我的用途 | 想持续获取的内容或想完成的任务 |
| 观察时间 | 本次检查的日期 |
| 数字范围 | 当前人数、历史起止日期、采样数量 |
| 内容依据 | 两三条相关消息的原始链接 |
| 信息缺口 | 缺少的历史、简介或无法打开的链接 |
| 下次检查 | 准备回看的日期与待核实问题 |

保留这份记录后，下一次打开[排行榜](/rank/)时，就能把新数据与自己的观察联系起来。需要先建立候选清单，可以继续阅读[查找频道指南](/guides/find-telegram-channels/)。
