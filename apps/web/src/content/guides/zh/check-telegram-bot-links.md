在[机器人目录](/bot/)里找到一个看起来合适的工具后，可以把核对分成四步。先确认对象，再确认入口，随后试用具体功能，最后记录使用条件。每一步都有可以保存的依据，方便以后重新检查。

## 先给机器人写一张身份卡

将显示名称、完整用户名、项目维护方公开页面和用途放在同一份记录中。显示名称适合阅读，用户名用于核对实际打开的对象。

| 记录项 | 核对方法 |
| --- | --- |
| 显示名称 | 与目录条目和 Telegram 资料页对照 |
| 完整用户名 | 逐字符查看，留意数字、下划线和相近拼写 |
| 来源页面 | 从项目维护方公开的网页或频道寻找入口 |
| 预期用途 | 写下本次准备完成的一项任务 |
| 核对日期 | 保存本次检查的时间 |

目录简介来自公开资料。遇到自动翻译，可以用译文了解主题，再到原文中核对用户名和链接。功能名称与联系方式可以分别记录，避免把简介中提到的其他账号当成当前工具的入口。

## 再读完整的启动链接

普通会话入口通常使用 `https://t.me/<username>`。有些入口还带有 `?start=<parameter>`，让机器人收到额外的启动信息。Telegram 官方支持这种深链接机制，参数的实际用途由机器人定义。[Telegram 深链接说明](https://core.telegram.org/bots/features#deep-linking)

把原始链接完整保存，观察它是否包含参数。若一个工具有不同入口，可分别写下入口来源和启动后出现的功能，建立自己的对应记录。

### 用本站提交入口作一个例子

TGsearch 的[提交收录说明](/enroll/)提供本站机器人入口。网站上的提交按钮使用 `start=submit` 指定提交流程。启动该入口后，机器人会提示发送 Telegram 链接，再进入资料确认、分类和标签选择。

可以依次检查以下结果。

1. 页面说明和即将打开的机器人用户名一致。
2. 启动后出现提交链接的提示。
3. 发送公开链接后，显示的条目资料与目标相符。
4. 分类、标签和确认页反映了本次准备提交的内容。

这套方法也能用于核对其他工具的功能入口。把预期结果写清楚后，再观察实际返回的信息。

## 用一项低敏感任务完成初次试用

从帮助信息或公开功能说明中选一项操作。例如，信息查询工具可以先查询公开示例，文件工具可以使用专门准备的测试文件。记录输入、返回结果、耗时，以及是否出现新的操作要求。

Telegram 的机器人通常由外部开发者提供。官方 FAQ 说明，机器人能看到你发给它的消息及部分公开资料，并提醒用户妥善保护密码和 Telegram 验证码。把发送给工具的资料范围作为试用记录的一部分。[Telegram 机器人说明](https://telegram.org/faq#q-are-bots-safe)

## 把功能和使用条件放在一起

遇到次数限制、订阅、群组权限或外部网页时，记录具体要求及其来源。涉及群组管理的工具，还应核对申请的权限与准备使用的功能是否对应。

| 我准备做什么 | 需要补充确认什么 |
| --- | --- |
| 偶尔查询公开信息 | 免费额度、结果来源和更新时间 |
| 处理文件 | 支持格式、大小限制和资料处理说明 |
| 管理群组 | 所需权限、帮助文档和停用方式 |
| 长期使用 | 费用说明、维护通知与反馈渠道 |

初次试用后，用一句话记录结果，例如“已用公开示例完成查询，返回了来源链接，额度说明待查”。记录应反映你实际观察到的内容。

## 出现差异时怎样反馈

如果目录中的用户名、简介或入口有误，保留详情页链接、错误字段、原始资料链接和观察日期。通过本站机器人发送 `/support`，按提示提交这些信息，能帮助维护者定位条目。

完成核对后，再决定是否持续使用或比较其他候选。需要理解频道和群组的资料字段，可以继续阅读[目录数据指南](/guides/read-telegram-directory-data/)。
